# Source lifecycle (host library)

This module is an opt-in, provider-neutral ingestion boundary. It contains no service client, login flow, credentials, model calls, or scheduler. A trusted host supplies the current `CallerScope` through `withCaller`/`withRequest`, creates a connector, and calls `syncSourcePage`. Connection creation and raw page staging/application are **host-only** APIs, not agent tool inputs.

## Connector contract

A `SourceConnector` supplies immutable `provider`, `account_hash`, and `scope_hash` bindings and `changes(cursor, limit): Promise<unknown>`. `account_hash` is a stable SHA-256 digest of the nonsecret provider account identity, independent of permission changes. `scope_hash` is a SHA-256 digest of the host's effective nonsecret upstream permission scope. The host must derive both from trusted configuration, not an agent-provided account, credential, or authority. The inline upsert text is the fetch equivalent; the core never connects to a service itself.

A page contains only `next_cursor` and `changes`. An upsert contains `kind`, `external_id`, `revision`, `content`, and optional `occurred_at`; a deletion contains `kind` and `external_id`. Unknown fields, repeated external identities in a page, oversized input, and credential-shaped content/metadata are rejected. Limits are 200 changes, 512,000 serialized UTF-8 bytes, and 24,000 characters per text. A connector must honor the smaller caller-requested limit. Cursors are opaque noncredential checkpoint values, not access tokens. Scope hashes and conservative shape detection do not replace the host's responsibility to exclude credentials.

An unchanged cursor is allowed only for an empty page, including initial null→null polling. Empty pages can advance to another opaque cursor. Non-null→null reset is rejected: rebootstrap/reset is outside this slice. Idle pages are durably journaled and advance the connection CAS generation, but do not change the global source-content generation.

## Transactions and replay

`stageSourcePage` validates before writing and stores only a stable page hash and cursor identity. `applySourcePage` requires the same page bytes modulo canonical object-key ordering. It atomically materializes immutable revisions into episodes, purges replaced derived claims, advances the cursor using cursor **and** generation CAS, and acknowledges the journal. A crash before acknowledgement leaves a staged receipt; re-present the same page. An acknowledged replay returns the original counts with `replay: true` without advancing the cursor again. Competing pages cannot both commit.

Episode ids and revision identities are deterministic. A known revision with different content or occurrence metadata is a conflict; a seen older revision never becomes current again. A previously unseen opaque revision is ordered by the connector's trusted change stream, not by sorting revision strings. The host must preserve the stream's causal order. Embeddings are always deferred: lexical evidence is immediately available, vectors remain stale for the existing maintenance pass.

## Removal and derivation

Replacement retains superseded raw episodes for explicit `include_source_history` reads, but ordinary search, counts, citations, vectors, and context assembly serve current evidence only. Context assembly always refuses historical source text, even when a raw historical-read flag is supplied. Source-managed reads enforce current namespace read grants; source teardown uses delete grants.

Deletion and explicit forget permanently tombstone the **external identity**, not one revision. Upstream deletion and revocation are connection-scoped. Explicit user-forget additionally creates an immutable barrier keyed by **owner, namespace, provider, account hash, and external id**, across existing and future permission scopes/connections. A scope change cannot bypass that barrier; an independent account with a colliding external id remains independent. All matching raw revisions and directly cited same-owner/scope canonical memories are removed, together with their legitimate same-owner/scope manual successors. Revocation permanently disables the entire connection and purges its evidence. A connection cannot be silently recreated under the same owner/namespace/provider/account/scope binding. This slice provides no unforget, undelete, or reconnect override.

The purge also removes affected cached cluster prose, namespace/ancestor digests, navigation digests, and owned session summaries. Foreign citations or cross-scope/owner revision edges are not authority to delete unrelated canonical rows. Purge audit events contain identifiers only; historical mutation payloads for purged memory IDs and affected namespace/ancestor/global maintenance results/errors are redacted without deleting their audit IDs or status. Source-aware episode delete previews include all revisions and citation links removed by the cascade, not just the initially matched current row.

Hosts must call `forgetSourcesForMemory` **inside the forget transaction and before losing citations**; it may remove the canonical row itself. `deleteEpisodes` already invokes `forgetSourceEpisodes` transactionally. Any other evidence-deletion path must invoke that hook before removing provenance. `readSourceGeneration` and `sourceDerivedMemoryIds` fence async summary/cache writers and prohibit provenance-free cross-namespace promotion until a cross-scope derivation policy exists. Generation comparison and cache write must occur synchronously in one transaction after the await. These helpers return 0/[] only on genuinely pre-lifecycle stores; other database failures propagate.

Removal is a serving guarantee for tracked data, not secure erasure of SQLite free pages, WALs, migration backups, in-flight response buffers, or previously exported copies. This is not cryptographic forgetting. The module cannot retract external exports, recognize copied/reidentified objects, or discover unlinked manual copies made without actual citation/revision lineage. Explicit-forget identity scope does not extend to other namespaces or owners.
