# Eval: hierarchical funnel vs flat retrieval (P1)

Generated by `scripts/eval-funnel.ts`. Read-only, deterministic. See the spec at
`docs/specs/hierarchical-memory-p1.md`.

## Method

- **DB** (readonly): `~/Library/Application Support/engram-nodejs/engram.db`.
- **Engine**: `hybridSearch` with `vectorsAvailable = false` (FTS5 lexical only —
  zero embedding/network writes) and `touch: false` (no `last_accessed`/
  `access_count` stamping). Scoring clock fixed to the DB's own
  `MAX(created_at)`.
- **Namespace tree**: computed with pure `parseNamespacePath` / `ancestorPaths`
  (no `namespace_nodes` writes — safe pre-migration).
- **Probe set**: 30 queries sampled from the two largest namespaces (hive and cb),
  each derived from a source memory's rarest distinctive terms (entity terms when
  available, rare content tokens otherwise). Fixed RNG seed → reproducible.
- **Modes**:
  - *flat* — `hybridSearch` over the memory's whole flat namespace (pre-hierarchy
    behavior: one git-root = one bucket).
  - *funnel* — `hybridSearch` scoped to the session scope's deepest-known namespace
    prefix, ascends ancestors (`top_score < THETA` or `hits < K_MIN`)
    producing nav guide excerpts. Mirrors `handlers.ts` funnel logic.
- **Metrics**: recall@5, recall@10, mean context chars @k=5 (sum of returned
  content lengths), mean response JSON bytes (faithful `ok()`-shaped payload).

## Findings

1. **Funnel is safe — zero recall or context regression.** On today's data, flat
   and funnel are *byte-identical* on recall and context. The only delta is
   +181 bytes (+5.3%) of `scope_trace` metadata. This was the isolation-risk
   gate: funnel scoping does not degrade retrieval.
2. **The context win is latent, not broken.** Every probe's session scope equals
   its flat namespace (data lives in two git-root buckets: hive=2,995, cb=1,015).
   When `scope == namespace`, `deepestKnownPrefix` resolves to the same bucket and
   the funnel is behaviorally the same as flat — exactly as the spec intends. The
   savings appear only after P2 write-side scoping distributes memories into
   subdirectory scopes; the funnel retrieval path that produces the savings is
   already implemented and tested (funnel.test.ts).
3. **Recall@10 is 1.0 while recall@5 is 0.862** — the 4 misses rank at 10, 8, 7, 8
   (all within top-10). These are genuinely harder queries (source terms appear in
   several sibling memories), not scoping failures.
4. **Nav layer is unprimed.** `guideEntries = 0` everywhere because `namespace_nodes`
   has no digests (P2) and parent nodes have no cluster summaries. The `guide`
   channel is correctly wired but currently empty.

## Threshold calibration (`THETA`, `K_MIN`)

Normalized top-score histogram across the 29 flat probes:

| top score | probes |
| --- | --- |
| < 0.2 | 0 |
| 0.2 – 0.35 | 3 |
| 0.35 – 0.5 | 10 |
| ≥ 0.5 | 16 |

`THETA = 0.35` sits at the lower quartile: only 3/29 (~10%) genuine matches score
below it. That is exactly where ascent *should* fire — a top score < 0.35 means the
leaf produced weak matches and the parent nav layer is worth consulting. **Keep
`THETA = 0.35`.** `K_MIN = 3` is unexercised (no thin leaves exist yet) but is a
sane floor: a leaf with < 3 hits is thin by any reasonable definition. **Keep
`K_MIN = 3`**, re-tune against P2 data when real thin scopes exist.

## Projected savings after P2 scoping (analytical, from real content-length stats)

| Namespace | memories | avg content chars | flat context @5 est. |
| --- | --- | --- | --- |
| hive | 2,995 | 327 | ~1,067 (measured) |
| cb | 1,015 | 634 | ~1,439 (measured) |

Funnel context at recall scales with the *scope's* share of the namespace. If the
2,995 hive memories are later distributed across S subdirectory scopes of roughly
equal size, funnel context ≈ `(n_scope / N) × flat_context + guide`, i.e.:

- S = 10 → ~11% of flat context (≈ 117 chars for hive)
- S = 50 → ~2% of flat context (≈ 23 chars)
- S = 200 → ~0.5%

The multiplier is `scope_isolation_ratio = n_scope / N`; the funnel's value grows
monotonically with write-side scoping granularity. This is the P2 work item, not a
gap in P1 retrieval.

## Caveats

- **Flat corpus**: today's namespaces are two large flat buckets; the funnel and
  flat baselines therefore coincide. The eval proves safety and isolates the
  savings to scoping granularity — it cannot yet show an end-to-end savings number.
- **Lexical-only**: vectors are disabled for determinism and side-effect freedom;
  recall figures are a lower bound vs the full hybrid FTS+vector path.
- **1 probe dropped**: `/Users/locc/git/research/hive/bdc9b342…` whose own terms do
  not FTS-match its content (likely content with no indexable distinctive token);
  an artificial (broken) probe, not a recall deficiency.
- **Digest excluded from byte parity**: the `digest` field is identical across
  modes by construction, so it does not affect the flat-vs-funnel delta.
